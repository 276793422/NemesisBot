# 项目类型专项检查

作者：NemesisZoo

## 使用规则

按 PRD 的实际业务、运行环境和交付物确定项目类型，读取公共规则及命中的小节。混合系统按组件分别适用；未匹配类型使用公共规则，并补充有需求依据的领域问题。不得把 Web 作为所有项目的默认结构。

各项是需要判定的问题，不是默认新增的功能、组件或数值门槛。将适用项映射为“来源与适用理由 → 质量目标及条件 → 设计与取舍 → 实施任务及输出 → 验收办法与证据”。不适用项简述理由，缺少关键输入时列为待确认；建议目标标明依据和确认节点，不冒充 PRD 要求。

专项提示不能替代多方案比较。语言、框架、存储、队列、容器、GPU 或服务拆分均按实际需求和团队能力选择；不设统一用户数量、响应秒数、层数或固定候选数量门槛。

## 公共运行与选型检查

| 检查问题 | 需要落地的设计与证据 |
| --- | --- |
| 团队能否构建、发布和长期维护？ | 已有能力、依赖成熟度、部署责任、运行成本及自研／复用选择依据；未知成本注明输入缺口。 |
| 边界失败如何影响整体？ | 实际外部依赖的超时、重试、幂等、停止与恢复条件；故障注入或隔离演练的预期，不默认增加熔断器或队列。 |
| 关键数据如何生存与恢复？ | 数据归属、事务、保留与删除、兼容迁移、适用备份恢复；明确可恢复点和核对办法，未提供恢复指标时待确认。 |
| 如何发现运行中的业务失败？ | 关键业务结果与资源指标、错误日志及必要的追踪；说明观测位置和行动责任，避免记录无必要的敏感内容。 |
| 如何安全演进和替换？ | 接口兼容、数据版本、发布后检查、回退限制、替换成本和触发条件；用相应任务和验证证明准备程度。 |

## 交互与状态组织（按需）

存在用户界面，或框架明确采用 MVC 等表现层约定时适用。根据交互、状态和测试需求选择，沿用框架术语的实际含义，不因模式知名就强制套用。系统部署方式、领域建模和表现层模式可分别选择并组合。

| 候选模式 | 可考虑的场景 | 需要权衡和核验的内容 |
| --- | --- | --- |
| MVC | 请求处理与视图呈现分离，或框架已有清晰 MVC 约定 | Controller、Model 与 View 的实际职责；避免控制器承担所有业务和持久化逻辑，不能将 Model 只理解为数据库表。 |
| MVP | 希望通过视图接口隔离 UI，把交互编排交给 Presenter | View/Presenter 契约、双向协作与生命周期、测试替身的价值及新增接口成本。 |
| MVVM | 视图状态与命令需要独立表达，框架支持数据绑定或状态映射 | ViewModel 的可观察状态、命令、绑定与清理；避免把领域规则或平台资源无限堆入 ViewModel。 |
| MVI／单向数据流 | 多来源事件、复杂共享状态，期望状态变化显式且可追踪 | 事件到状态及副作用的边界、竞态处理、恢复与调试收益，对比样板和学习成本。 |
| 轻量组件或页面状态 | 状态局部、交互简单，额外抽象没有明确收益 | 状态唯一归属及提升边界、必要的交互测试，不默认引入全局 Store 或多层包装。 |

明确输入事件、状态归属、业务用例调用、异步结果和视图更新的流向；按场景验证加载、成功、拒绝、失败、取消、乱序响应和适用的页面／进程重建。只安排实际存在的行为。跨页面业务不变量留在负责的业务层，界面状态校验与反馈按其职责处理。

区分持久业务状态、客户端共享状态与页面临时状态，说明各自的权威来源、修改者、派生关系、保存／释放及重建条件；不把同一业务事实在多个 ViewModel 或 Store 中各自维护为独立真值。简单页面可以采用局部状态，无须为完整呈现模式而建立额外类或接口。

异步交互按业务语义明确晚到结果应覆盖、合并、忽略还是提示冲突，以及何时允许再次提交。取消界面等待、取消传输与撤销业务动作分别定义；取消或页面销毁不能直接证明服务端未提交。写操作结果未知时沿用行为契约的结果核对办法，避免重复副作用。事件顺序和恢复后的预期状态须有需求或明确设计建议依据，不预设所有场景都适用“最新结果覆盖”。

将这些规则关联到具体实现任务与验收观察点；页面样式、截图或绑定语法通过不足以证明状态与业务结果正确。

同一交互任务使用相同业务契约比较方案。若差异会影响团队实现、工期或维护成本，则纳入多方案评审由开发人员选定；已接受的模式和例行细节不重新审批。

## Web／API 服务

触发：HTTP/API、多用户在线服务、浏览器与后端协作。

| 检查方向 | 需回答的问题与验证方式 |
| --- | --- |
| 接口与权限 | 谁调用、是否需要身份和授权、哪些输入应拒绝、错误及版本如何兼容；按实际角色验证越权与拒绝，不给无身份需求的本机工具强加登录。 |
| 表现与请求组织 | 有服务端视图或前端应用时按上节判断 MVC 或客户端状态模式；明确请求处理与应用用例边界，纯 API 不为凑 MVC 增加 View。 |
| 并发与数据正确性 | 关键写操作的事务边界、重复请求、竞争更新和超时后结果；验证业务不变量及失败后数据，不能仅看 HTTP 状态。 |
| 容量与运行单元 | 负载模型、数据规模、响应与资源目标来自何处；比较适用的同步／异步和部署形式，在代表性条件下验证，不凭用户数量推导微服务或 Kubernetes。 |
| 外部集成 | 超时、重试、速率和契约兼容如何处理；分别验证调用失败、重复回调和依赖不可用，说明用户可观察结果。 |

## 移动端应用

触发：iOS、Android 或跨平台移动客户端。

| 检查方向 | 需回答的问题与验证方式 |
| --- | --- |
| 平台与生命周期 | 最低系统、实际设备范围、冷启动、后台限制、权限撤回和进程回收；在目标设备验证恢复与功能结果，指标由本项目确定。 |
| 交互架构与状态 | 按实际框架比较 MVC、MVP、MVVM、MVI 等适用模式及轻量方案；验证导航、异步结果、状态恢复和业务层边界，不按平台名称预设唯一模式。 |
| 本地与联网行为 | 哪些功能离线可用、缓存何时失效、离线修改如何同步、冲突及身份映射如何处理；验证断网、重连、重复提交及多端冲突。 |
| 数据与交互 | 按需求确定凭据保管、本地数据清理、深链、推送或无障碍；只为适用能力安排验证，不能默认项目需要推送或登录。 |
| 分发与兼容 | 签名、测试分发、目标渠道规则、客户端与服务端版本兼容及失败恢复；核实适用平台政策与版本，不把示例工具或热更新能力当作既定事实。 |

## AI／ML／大模型应用

触发：模型训练、推理、检索增强、模型服务或智能应用。

| 检查方向 | 需回答的问题与验证方式 |
| --- | --- |
| 实际模型生命周期 | 仅推理、调用外部模型、微调还是完整训练？按实际范围确定流程；仅推理项目不自动增加训练平台、特征库或模型注册中心。 |
| 效果与行为 | 代表性评估集、标注／参考答案、正确性或任务成功率、拒绝与失败结果如何判定；固定评估数据与模型／提示／检索配置版本，区分模型质量和服务可用性。 |
| 资源与成本 | CPU/GPU/NPU 是否需要，模型大小、内存／显存、并发、输入输出长度及预算依据是什么；以目标硬件与负载实测，不把 GPU 或特定调度方式当作必需。 |
| 数据与可复现 | 数据来源与使用限制、数据和模型版本关系、适用随机性、索引和提示配置如何留证；存在训练时再追踪训练数据到模型产物。 |
| 发布与退化 | 模型或外部提供方不可用、超时、效果回退或版本替换如何处理；按项目确定降级、离线能力和回滚验证，效果阈值缺失时待确认。 |

## 数据管道与数据平台

触发：ETL/ELT、批处理、流处理、数据仓库、数据湖或分析链路。

| 检查方向 | 需回答的问题与验证方式 |
| --- | --- |
| 来源与语义 | 源协议、全量／增量／变更捕获、模式版本、字段质量与血缘如何定义；验证抽取边界、类型变化和源数据缺失。 |
| 时间与新鲜度 | 业务容许延迟、吞吐、窗口、迟到／乱序及水位语义是什么；用代表性数据验证，不按统一秒数阈值强制流处理。 |
| 重放与一致性 | 重跑、补数、断点、重复与部分提交如何影响业务结果；端到端交付语义以源、处理和落库共同验证，不能仅凭框架声明“恰好一次”。 |
| 压力与恢复 | 积压、背压、下游失败和历史重处理如何保护数据与既有结果；检查数据核对、隔离／修复、恢复时间及保留条件。 |

## 嵌入式／固件／IoT

触发：MCU、RTOS、硬件驱动、固件或边缘设备。仅有设备接入的服务端不自动承担固件设计职责。

| 检查方向 | 需回答的问题与验证方式 |
| --- | --- |
| 硬件与实时约束 | 芯片、板卡、时钟、外设、最坏响应／执行时间、RAM/Flash 与功耗预算依据是什么；在对应硬件与配置下测量，不套用统一门槛。 |
| 并发与边界 | 裸机／RTOS、任务与中断职责、共享状态、缓冲及溢出如何处理；按时序、争用、资源耗尽验证，硬件抽象以实际可移植需求为依据。 |
| 协议与失效 | 电气／协议约束、帧、超时、重连、掉电及异常安全状态如何定义；用协议用例、故障注入及适用硬件在环验证。 |
| 交付与升级 | 交叉编译、烧录、调试、配置与硬件版本如何关联；有升级需求时再定义包校验、兼容、断电和回退验证，不自动引入 OTA。 |

## 桌面端／CLI／系统工具

触发：本机桌面程序、命令行、系统服务、文件／进程／操作系统 API 工具。此项为本技能补充的通用工程检查。

| 检查方向 | 需回答的问题与验证方式 |
| --- | --- |
| 目标环境与权限 | 操作系统、架构、SDK/运行时、用户权限和实际离线要求如何确定；在目标环境验证安装、运行及权限拒绝。 |
| 本机状态与资源 | 文件路径、锁、编码、配置、进程和句柄的所有权与生命周期如何管理；验证中断、重复运行、释放和不应修改的数据。 |
| 交互与自动化契约 | GUI 交互状态或 CLI 参数、退出码、标准输出／错误及取消语义是什么；用实际调用与前后状态验证，不强制套用 HTTP/API 模板。 |
| 界面模式适用性 | 桌面 GUI 按交互复杂度选择 MVC、MVP、MVVM、MVI 或轻量状态；CLI／无界面服务只保留所需的输入、用例与输出组织，不强制建立视图模型。 |
| 发布与恢复 | 打包、签名及更新是否适用，用户数据和旧配置如何兼容；验证目标环境升级、回退或修复路径，不默认需要容器或独立后端。 |
